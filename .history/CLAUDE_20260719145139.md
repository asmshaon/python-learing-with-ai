# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A personal Python **learning** repo that follows the full Python curriculum
(basics → OOP → file handling → libraries → machine learning → DSA → databases).
It is not an application — it is a collection of study chapters.

**One file per chapter**, under `chapters/<section>/`. Every chapter file has:
1. A top **docstring with Notes** explaining the concept.
2. **Three problems** as `problem_1()`, `problem_2()`, `problem_3()`, each with a
   worked solution that `return`s its result.
3. A `if __name__ == "__main__":` block that runs and prints all three.

`chapters/_template.py` is the starting point for any new chapter.

## Commands

Everything runs with the system Python (3.12); no build step.

```bash
python3 chapters/01_basics/01_syntax.py      # run one chapter

# run every chapter (quick smoke check that nothing is broken):
find chapters -name '*.py' -not -name '_template.py' -exec python3 {} \;
```

Sections 04 (Libraries), 05 (Machine Learning), and 07 (Databases) need
third-party packages — install into a virtualenv first:

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## Conventions (follow these when filling in chapters)

- Keep each solution self-contained in its `problem_N()` function and **return**
  the result (so it is testable) rather than only printing inside the function.
- Put explanations in the module docstring's **Notes** section, not scattered
  comments — comments in the body should explain non-obvious steps only.
- **Do not put a literal `"""` inside the module docstring** — it closes the
  docstring and breaks the file. Describe triple-quotes in words instead.
- Files are numbered in curriculum order within their section folder
  (`04_variables.py`). Keep the numeric prefix aligned with the list below.
- Standard library only for sections 01–03 and 06. Reserve pip installs for
  04, 05, 07.
- After editing a chapter, run it to confirm it executes cleanly.
- Update the progress table and section counts in `README.md` when a chapter is
  completed.
